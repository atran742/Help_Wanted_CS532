|  DB01 | Database | The *SignMeUp* system shall be capable of maintaining information for multiple students, departments, courses, and course advisors, It is to be expected that courses may be associated with multiple students and each student may be associated with multiple courses. The system shall be designed, therefore, with both one-to-many and many-to-many structures, which is consistent with the use of a relational database to store information. |  Database Administrator(s) |
| DB02 | Database | All tables created under the *SignMeUp* database will have security restrictions through row-level security that will prevent unauthorized groups from seeing sensitive information regarding students. Students should also not have access to any administrative tables if they have not been granted permission. |  Database Administrator(s) |
| ER01 | Error Handling | If a user attempts to input information out of sequence, or the information entered is inconsistent with requirements for information entry, the entry shall be rejected, and an error message shall indicate: 1\) the reason for the rejection, and 2\) the minimum requirements that must be met for the entry to be accepted. | All Users |
| ER02 | Error Handling | SignMeUp shall prevent functions that require a student record from being performed until the required student information has been entered. | All Users |
| HL01 |  Help Function | To assist personnel in learning to use *SignMeUp*, and to help them solve problems encountered while using the system, *SignMeUp* shall incorporate an on-line help function. To facilitate access by the *SignMeUp* end-user, the on-line help function shall be context sensitive. It shall also be sufficiently detailed to provide answers to most of the questions asked by *SignMeUp* end-users. The help facility will include overall system functions, transaction descriptions, screen descriptions, and data fields. Users will have the ability to update the help screens under security control provided by the system. |  Authorized Users |
|  HL02 |  Help Function | *SignMeUp* shall allow a user to ask for and obtain help for each entry or inquiry module or screen, while the user is in that module or screen. The "help" system shall provide essential information for the module or screen's purpose and usage. |   All Users |
|  HL03 |  Help Function | *SignMeUp* shall allow the user to ask for and obtain "help" for each individual field, while the cursor is in that field, for each entry and inquiry screen. The "help" function shall give the user a brief explanation of the field requirement(s) for that particular field, including whether the field is mandatory (i.e., data MUST be entered in the particular field, if applicable).  |   All Users |
|  NV01 |  Navigation | The system will be menu driven. There will be standardized movement from screen to screen without having to return to the main menu. System messages will be standardized.  |  All Users |

|  DB03 |  Database | *SignMeUp* shall use pre-assigned roles and privileges to determine which objects each user can access and which actions they can perform. |  System Administrator(s) |

|  NV03 |  Navigation | The user shall be able to return to a screen already processed to add optional information, or to modify information previously entered. As a minimum, return to a screen already processed shall be accomplished by selecting the desired screen from a menu.  | All Users |

|  RP01 |  Reporting | All printed reports should have the capability of being viewed on the workstation before printing. Reports should be accessible as a whole or in parts. |  Reporting Users |
